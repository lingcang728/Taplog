# 素材登记表与实验讲座池

选取标准：**全部用中文讲座（单人普通话主讲，30–50 分钟）**。每场要有带时间戳的字幕，内容是有推理过程的技术讲座，我们找的被试大概率没看过。素材只在本地做研究用。

“远距离补充”的定义：某个结论讲完 **5 分钟以上**，讲者才补充适用条件、改口，或在问答里修正。间隔从这个结论**第一次**出现算起。

## 二、C 类统计语料池（10 场）

**核对方法（11/23）：**
1. 登记表原来写的每个“后置补充”时间点，都打开字幕前后各看约 1 分钟，判断是否成立。
2. 用脚本在每场字幕里搜两类句子：一类带限制词（“限制”“缺点”“代价”“并不是”“很遗憾”“不一定”“没有解决”等），一类回指前文并带转折（“刚才讲的……但是”）。对每一处命中，往前找它补充的是哪个结论。
3. C 类没有逐句通读。像 L01 28:12 “我们也有一些阻碍”这种不带关键词的补充，可能漏掉。报告里要写明这一点。

**核对结果：** 原登记表的 9 处判断，按“隔 5 分钟以上”的标准**都不成立**。大多是把“讲问题、再讲方案”的正常结构，或者别人的观点，当成了讲者给自己补充限制。只有第 4 场有一处约 6 分钟的边界情况。

**这对报告意味着什么：** 13 场里只有 2 场（L01、L02）有明确的远距离补充，而且这 2 场是我们专门挑出来的。所以报告 Background 不能写“技术讲座普遍存在远距离补充”，要写成：
- 这种情况不是每场都有。它集中出现在“经验分享、推荐方案”类的讲座里：讲者先给结论，最后才讲“我们也遇到了阻碍”。
- 正因为不常见，读者没有防备。一旦出现，只看单个时间点就很容易漏掉。

## 三、本地文件与复用说明

讲座视频、时间戳字幕和逐字稿不放进本仓库（体积大，也有版权问题），在黄奕滔本地：`实用人机交互/讲座视频素材/`。

以后要补充下载其他 B 站讲座，可以用黄奕滔本地的下载脚本：
```bash
python3 _scripts/download_lecture.py "https://www.bilibili.com/video/BVxxxxxx"
```
它会下载视频、提取 `.srt` 字幕，并生成带时间戳的逐字稿。

自动扫描的原始结果见 [字幕扫描结果](字幕扫描结果.md)。那里命中的大多是普通复述，只能当线索用。
