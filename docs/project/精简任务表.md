# 精简任务表（Group 17）

**一句话：** 做一个 demo：把英文技术讲座变成一张可以点的图，点开能回听原声，听讲座时能边录边问。找真人试一试，看它是不是比文字纪要更好懂。最后把整个过程写成报告。

详细版见 [任务表](任务表.md)，这里只列真正要做的事。

---

## 1. 先确认问题是真的（12/4 前）

- [ ] 找 3 场英文技术讲座：2 场用来测试，1 场用来试实时问答（李安逸、李祈恺）
  - 讲座要求：30–50 分钟、有英文字幕、概念多、能画成图
  - 每场列出：主要概念、概念之间的关系、哪个点后面又讲了一遍
- [ ] 用同一场讲座试飞书、通义、钉钉，截图记下它们做不到什么（林韦丞）
- [ ] 问 3–5 个真人（黄奕滔牵头，每人至少问 1 个）
  - 问这几件事：最近一次回看讲座，哪里没看懂？怎么找原话？想不想边听边问？
- [ ] 在网上找 50 条左右的吐槽，分几类，数一数每类多少条（李祈恺）
- [ ] 全组碰一次：证据够不够？重点要不要调整？

## 2. 想清楚 demo 长什么样（12/8 前）

- [ ] 定 5–6 条设计原则（黄奕翔）
- [ ] 画出 2–3 种“图”的样子，可以让 AI 先出草稿（黄奕翔）
- [ ] 每个人走一遍，再找 3 个同学试一下，选定一种（全员）

## 3. 做 demo（12/15 前）

- [ ] 先试通实时问答的技术：阿里转写 + DeepSeek（黄奕翔 · 12/6）
- [ ] 把 3 场讲座整理成数据（李祈恺、李安逸）
  - 内容包括：概念、关系、每个概念对应的原声片段、“后面还讲过”的片段
  - AI 先出，人逐条核对
- [ ] 做图版（黄奕翔）。要能走通这条路径：点图 → 听原声 → 看到“后面还讲过” → 回到图上
- [ ] 做文字版：同一份数据排成文字纪要，用来对比（黄奕翔）
- [ ] 做实时问答：边播边转写，随时提问，回答标出出自哪一段（黄奕翔）
- [ ] 做测试模式：切换版本、出题、记录答案和用时、导出表格（李安逸）
- [ ] 找 2 个人完整走一遍，确认不出错（黄奕滔）

开发规则：Agent 要用 Taplog 或其他现成代码，必须先问组员。

## 4. 找人测（12/20 前）

- [ ] 请别组 3–5 人挑毛病，把严重的问题改掉（林韦丞组织，黄奕翔改）
- [ ] 写测试题和标准答案（李祈恺、黄奕滔）
  - 每场讲座出 4 题：关系题 2 道、找原话 1 道、“后面还讲过” 1 道
- [ ] 先找 1–2 人试测，题目有问题就改（黄奕滔）
- [ ] 正式测 6–8 个真人（黄奕滔主持，组员轮流记录）
  - 每人两个版本都用：一场讲座用图版，另一场用文字版
  - 最后试一次实时问答，填问卷，再聊 5 分钟
- [ ] 整理数据：正确率、用时、问卷分数，做 3–4 张图（黄奕滔、李祈恺）

## 5. 讲出来、写下来

- [ ] 做 PPT，排练两次（全员 · 答辩前）
- [ ] 写报告：把上面每一步按“做了什么 → 发现了什么 → 改了什么”写下来（全员 · 答辩后交）
